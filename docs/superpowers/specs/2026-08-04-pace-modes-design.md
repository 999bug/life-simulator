# 节奏档位设计（第一弹）

日期：2026-08-04
状态：已批准

## 背景

当前游戏只有两个极端节奏：手动全量（490 事件、每岁中位 15 个选项、一局 1.5-3 小时）与 ⚡快速模拟（自动随机、约 2 分钟、零参与）。中间缺少「精简但仍有选择」的档位：想快速走完一生的人被迫面对每岁十几个选择，想慢慢体验的人没有任何辅助。

目标：提供**密度**与**打字速度**两个独立维度，组合出多种节奏。

## 档位模型

| 维度 | 档位 | 说明 |
|---|---|---|
| 密度 `paceMode` | `full`（沉浸）/ `lite`（精简） | 开局选定，中途不可切 |
| 打字 `typeSpeed` | `slow` / `normal` / `fast` + 点击跳过 | 开局选定，游戏内可随时切换 |

- `lite` 目标：一局约 200 个事件 ≈ 40-60 分钟（`full` 为 490 个、1.5-3 小时）
- 打字速度：slow 50-70ms / normal 25-45ms（现状）/ fast 8-15ms 每字符
- 打字中点击对话框立即显示全文（现状打字中点击无效）

## 数据事实（抽样规则依据）

- 事件总数 490：主线（2 位数字后缀 id）371 个、模拟（4 位数字后缀 id）119 个
- 主线覆盖 0-90 岁（每岁 1-7 个）；模拟事件集中在 3-12 岁（每岁 4-11 个），其余零散
- flag 依赖：同岁 10 处、跨岁（产出者在更小岁）139 处、悬空 0

**结论**：精简模式必须对主线也抽样（运行时过滤，不改数据文件，与 prune-events「主线一字不改」规则不冲突）；flag 闭包必须跨岁回溯。

## 引擎层：`filterEvents(events, mode, seed)`（src/engine/events.ts）

纯函数、确定性抽样，三步：

1. **密度目标**：0-2 岁全保留；3-12 岁每岁 3 个；13-75 岁每岁 2 个；76+ 岁每岁 2 个（主线 1 + 模拟按需补）
2. **主线优先**：同岁组内主线（2 位 id）优先进入子集，模拟事件按 seed 抽取补足目标密度
3. **flag 闭包**：迭代补齐——子集内所有消费事件（`has_flags`）的 flag 产出者必须也在子集内（跨岁回溯加入）；闭包稳定后结束，闭包加入的产出者不再二次裁剪（可能使个别岁超过目标密度，总量可控）

调用链：`shuffleEvents(filterEvents(EVENTS, mode, seed), seed)`，过滤与洗牌共用同一 seed → 同 seed 同结果，读档确定性重建。

## 状态与存档（src/hooks/useGame.ts）

- `RuntimeState` 加 `paceMode`、`typeSpeed` 字段；`SaveData` 同步加两个字段
- 旧存档无字段 → 兜底 `full` + `normal`
- `START_GAME` 接收档位参数；`CONTINUE_GAME` 按存档档位重建数组，`eventIndex` 语义不变
- 新 action `SET_TYPE_SPEED`：只改渲染状态，不碰事件数组 → 游戏内切换零风险
- ⚡快速模拟不受影响，保持 `instant` 全跳过

## UI

- **TitleScreen**：「开始人生」按钮上方加节奏选择（沉浸/精简两卡片，默认沉浸），精简卡片标注「每岁约 2-3 个选择 · 一局约 1 小时」
- **GameScreen**：底部对话框区右上角加打字速度小切换（慢/中/快 三个小圆钮，当前档高亮）
- **DialogBox**：`speedMs` prop 替换硬编码 `25 + Math.random() * 20`；打字中点击 → 立即 complete

## 风险与边界

- `lite` 抽样后 flag 剧情链仍可能静默跳过（闭包保证产出者在子集，但 `min_attrs` 等条件仍可能不满足）——与 `full` 模式行为一致，可接受
- 游戏内仅打字速度可切；密度切换涉及数组重建与索引重定位，边界多，本期不做
